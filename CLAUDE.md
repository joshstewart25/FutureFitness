When developing in this repo, I would like you to keep a few things in mind:
1. Readability over complexity - Write things in a way that an average-level developer would understand. Even if it is less concise or less "clever", we want to make sure humans can understand what was written.
2. Keep it light on the comments - We want descriptors for anything that's overly complicated or has nuance but don't throw comments on every little function if it's self-explanatory.
3. Build for scale - According to the README, this is supposed to be a very simple application, but still develop it with room to grow as if someone wanted to continue adding on here.
4. Don't assume everything - If you are not sure about a particular direction, don't make assumptions that one path is right vs. another. Always double-check with the developer.
5. Use leading architecture principles - Use MVVM as the basis for structure, for example. We want to make sure that the application is written in a way that most Android devs can understand if they need to jump in from another project.
6. KISS principle - Last but not least, always keep things to their simplest forms. No need to convolute something unnecessarily.
